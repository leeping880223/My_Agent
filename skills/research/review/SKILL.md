# review：論文四階段複習驗證

## 目的

確認使用者真正掌握整篇論文，而不是「看過就以為懂了」。以使用者主動輸出為主、agent 提問為輔。

## 前置準備

1. 確認要複習的論文，讀取該論文資料夾的 `README.md`、`supplements.md`，以及 `data/knowledge-map.md`。
2. 向使用者說明接下來的四階段流程。

## 四階段驗證（依序進行，每一階段通過才進下一階段）

### 階段一：懂（理解概念）
- 請使用者用自己的話解釋論文的核心概念與方法。
- Agent 針對模糊處追問「為什麼」，確認不是背誦而是理解。
- 判定標準：能正確解釋每個關鍵概念的原理。

### 階段二：會（能應用）
- 出應用型問題，例如：「如果把這個方法用在 X 情境會發生什麼事？」「這個方法在什麼條件下會失效？」
- 判定標準：能將方法遷移到論文以外的情境並正確推理。

### 階段三：記（記得關鍵細節）
- 抽問關鍵細節：重要公式的形式與意義、實驗設定、主要數據結果、與 baseline 的差異。
- 判定標準：不看論文能答出關鍵細節（允許小誤差，但方向要對）。

### 階段四：說（能完整講給別人聽）
- 請使用者假裝對「完全沒讀過這篇論文的同學」做一次 5–10 分鐘的完整口頭說明。
- Agent 扮演聽眾，在不清楚的地方舉手發問。
- 判定標準：說明有完整結構（動機 → 方法 → 實驗 → 結論），且能回答聽眾的即席提問。

## 間隔重複（Spaced Repetition）

複習不是一次性的測驗，要讓錯過的東西反覆回來：

1. **維護「待複習清單」**：寫在該論文 `README.md` 的專屬區塊，記錄每個項目、答錯／不熟的日期、錯在哪裡。
   - 使用者答錯、答不出、或答得含糊的項目 → 立刻加入清單。
   - **同一項目重複答錯要標記次數**，反覆出錯的代表是頑固誤解，優先處理。
2. **當次複習內就要回考**：教過之後不要就過了，隔幾題換個角度再問一次，確認是真的懂而不是剛聽完的短期記憶。
3. **跨次複習要回考**：下次執行 review 時，先從待複習清單抽考，通過才移出清單。
4. **已經會的也要抽考**：不要只考不會的。每次複習隨機抽幾個「已通過」的舊項目確認沒有退步——理解程度會退步，紀錄要能反映這件事。

## 結果更新

1. **該論文的 README.md**：
   - 記錄本次複習日期與四階段的通過狀況。
   - 更新每個重點的理解程度（可能升級，也可能發現退步而降級）。
2. **`data/knowledge-map.md`**：同步更新相關概念的理解程度。
3. 未通過的階段：條列具體弱點，並建議下次複習的重點；必要時建議回頭執行 `background-extension`。
