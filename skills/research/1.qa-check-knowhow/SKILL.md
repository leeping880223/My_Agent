# qa-check-knowhow：論文重點整理與理解程度檢測

## 目的

使用者提供一篇文獻後，先幫使用者整理重點，再透過問答確認使用者對此領域的理解程度，作為後續補充教學（background-extension）與投影片製作（slide-maker）的依據。

## 執行步驟

1. **閱讀文獻**
   - 使用者提供論文（PDF、URL 或文字）後，完整閱讀。
   - 條列這篇論文的所有重點：研究問題、方法、關鍵概念、重要公式、實驗設計、結論。

2. **建立論文資料夾**
   - 在 `data/paper-library/` 底下建立該論文的資料夾，命名格式：`<年份>-<第一作者>-<簡短題名>`（例如 `2024-vaswani-attention`）。
   - 複製 `data/paper-library/_template/` 的結構（README.md、supplements.md、slides/）到新資料夾。
   - **把論文原始檔複製進資料夾，統一命名為 `paper.pdf`**（使用者給的是 URL 就下載；是純文字就存成 `paper.md`）。之後 background-extension、slide-maker、review 都直接讀這個檔案，不依賴使用者當初提供的路徑。

3. **Q&A 前置確認：使用者與本篇的接觸程度**
   - 出題前，先詢問使用者屬於下列哪一種，並依此調整出題策略：
     1. **完全沒接觸過相關知識** → 從領域基礎觀念問起，題目少而淺，主要目的是標定缺口給 background-extension，預期大量「不懂」是正常的，不要讓使用者挫折。
     2. **接觸過相關知識，但尚未閱讀本篇** → 先測領域前置知識（判斷哪些已會），論文特有的貢獻用引導式問題帶出，重點放在「這篇和你已知的差在哪」。
     3. **大概掃過本篇，但細節不熟悉** → 主測核心概念與關鍵細節，用追問「為什麼」找出「以為懂但說不清」的地方（此類使用者最常見的盲區）。
     4. **完全讀過本篇，確認理解沒有問題** → 出進階驗證題：邊界情況、方法失效條件、與其他方法的對比，接近 review skill 的強度，目標是驗證而非教學。

4. **Q&A 測試理解程度**
   - **出題順序原則：從大概念逐漸往細節帶**，並根據前置確認的等級決定起點：
     - 等級低（1、2）：先問「這篇在解決什麼問題」「核心想法是什麼」這類大概念，確認大方向的理解狀態，再視回答決定要不要往下探；大概念都不穩就停在大概念，把細節留給 background-extension。
     - 等級高（3、4）：大概念快速帶過或跳過，直接問細項與原理（公式意義、機制、邊界情況）。
   - **等級 1、2：Q&A 的定位是「用提問搭鷹架」，不是測驗。** 問題序列要循序漸進，讓使用者在答題過程中同時建立背景知識架構與名詞熟悉度——後續的 `2.background-extension` 與 `3.slide-maker` 才有地基可接。理解程度的標定是這個過程的副產品，不是主要目的。
     - **名詞先出場、再入題**：任何專有名詞，必須先在前一題的教學、或使用者自己的回答裡出現並解釋過，才可以拿來當下一題的題目。沒出場過的名詞不能直接考。
     - **每題只前進一步**：新題與前一題之間只隔一個新概念；前一題的答案（或該題教學的結論）就是下一題的材料。
   - **出題可答性檢查（每一題出之前先自問）**：這題的答案，使用者能不能從「他既有的知識」或「題目本身給的材料」推出來？
     - **可以** → 出成開放問答題。例：問「Jacobian 的時間導數為什麼會多出一項」，使用者用高中微積分的乘法律就推得出來；例：問「少了度量會怎樣」，使用者從前一篇論文的既有知識就答得出來。
     - **不行，答案完全依賴本篇的新內容** → **不要出成開放問答題**，改走「**先教後驗**」：先把機制講清楚，再問檢驗題（請他換句話說／判斷後果／套用到自己的專案場景）。
     - 判準：**等級 1、2 的使用者，凡是「本篇特有的新機制」一律走先教後驗**；等級 3、4 才可以直接開放提問（他們讀過，手上有素材）。要求對方推導一個在他知識裡毫無掛鉤點的新概念，測到的不是理解程度，是挫折。
     - 提供對照選項、具體情境、或可套用的既有公式，都算「題目本身給的材料」——這是把不可答的題目改造成可答題目的標準手法。
     - **使用者反映「答不出來／太抽象」時，先檢討題目的掛鉤點，不要檢討使用者的程度。** 標準改造手法（由易到難）：①**比喻配對題**——給兩個具體的生活情境，問哪個對應哪個機制（挑比喻時要檢查它夾帶的附帶暗示，見 `2.background-extension` 步驟 3；錯的比喻會直接造成誤解）；②**選擇題／判斷後果題**——給定情境問會發生什麼；③改回開放題。注意「請用自己的話說 A 和 B 本質差在哪」看似簡單，其實是抽象比較題，對等級 1、2 偏難，應改用 ① 或 ②。
   - 針對每個重點，設計問題逐一詢問使用者（一次一題，避免轟炸）。
   - 問題應涵蓋：核心概念的定義、方法背後的原理、論文中出現但未詳細解釋的前置知識。
   - 根據回答，將每個重點的理解程度標記為以下等級之一：
     - `不懂`：完全沒接觸過或答錯
     - `略懂`：知道名詞但說不清原理
     - `懂`：能正確解釋
     - `精通`：能解釋並延伸應用

5. **寫入該論文的 README.md**
   - 依照 `_template/README.md` 的格式，記錄：論文基本資訊、每個重點的說明、以及使用者對每個重點的理解程度。

6. **更新第1層總 README.md（`data/paper-library/README.md`）**
   - 在已讀論文清單新增一列：論文標題、一句話重點概要、資料夾連結。

7. **更新 `data/knowledge-map.md`**
   - 將這篇論文的每個關鍵概念加入總表：概念名稱｜理解程度｜出處（連結到這篇論文的資料夾）。
   - 若概念已存在於總表，更新理解程度並在出處欄追加這篇論文的連結。

8. **收尾**
   - 向使用者總結：哪些概念已懂、哪些不懂。
   - 對於「不懂且論文中沒有解釋」的概念，建議接著執行 `2.background-extension`。
