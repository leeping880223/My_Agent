# plan-adjuster：計畫調整

## 目的

讓計畫跟著現實變化，同時留下完整的調整軌跡——這些軌跡日後是 `story-builder` 面試故事（決策過程）的重要素材。

## 執行步驟

1. **了解變化**
   - 詢問或確認：是誰／什麼觸發了這次調整？（領導回饋、實驗結果、資源變化、自己的判斷）
   - 具體的新方向或新要求是什麼？

2. **讀取現有計畫**
   - 讀取 `data/goals.md`，確認目前「已完成」與「即將要做」的內容。

3. **判斷調整幅度**
   - **小調整**：改任務順序、調時程、增刪個別任務 → 直接修改對應項目。
   - **大重排**：目標本身改變、大部分任務不再適用 → 重寫「即將要做」區。

4. **決定「不再是主線」的任務怎麼處置**（三選一，不要預設只有刪或留）
   - **已中止**：已投入但方向作廢 → 移到「已完成」區並註明「（已中止）」，保留歷史與投入的軌跡。
   - **降級為選配**：還沒做、也不是主線，但仍有價值（demo 效果、外部單位期待、日後可能用上）→ **留在「即將要做」區的最後，獨立一節標明「選配」，並寫清楚「什麼條件下才做」與降級的理由**。例：2026-08-20 把「行走與搬運」整段降級為選配，理由是指導教授的步驟清單沒有它、且沒有好的應用場景，但合作單位想看，故保留為 demo 附加項。
   - **刪除**：完全無關且無保留價值 → 直接移除，但變更紀錄裡要寫明刪了什麼。
   - 判準：**「這件事將來還有人會問起嗎？」** 會，就降級或標中止；不會，才刪。

5. **修改 `data/goals.md`**
   - 依上述判斷更新計畫，維持原有的兩區格式。
   - 「已完成」區的既有紀錄一律保留，不刪除。

6. **記錄到 `data/plan-changelog.md`**
   - 追加一列，格式：

     | 日期 | 改變內容 | 原因 |
     |---|---|---|
     | YYYY-MM-DD | <改了什麼，簡述前後差異> | <為什麼改，包含觸發來源> |

7. **收尾**
   - 向使用者摘要：改了什麼、為什麼、新計畫的下一步是什麼。
   - 若這次轉向牽涉職涯方向，提醒使用者可能也要用 `job-matching` 更新職涯規劃。
