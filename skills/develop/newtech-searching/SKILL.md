# newtech-searching：現成方案與新工具搜尋

## 目的

「先找輪子，再造輪子」。避免把時間花在已有成熟開源方案的功能上，並讓使用者持續掌握領域內的新工具。

## 模式一：開發前搜尋（新功能開工前執行）

1. **定義需求**
   - 和使用者確認要開發的功能：輸入輸出、限制條件（語言、授權、部署環境、效能需求）。

2. **搜尋現成方案**
   - 使用網路搜尋，來源包含：GitHub、PyPI/npm 等套件庫、HuggingFace、相關領域的 awesome list。
   - 同時查閱 `data/dev-log/`，確認過去是否試過某些方案並已知不可行。

3. **評估與比較**
   - 對每個候選方案評估：功能覆蓋度、維護活躍度（最近 commit、issue 回應）、授權相容性、社群規模、與現有技術棧的整合成本。

4. **回報建議**
   - 以表格比較候選方案，給出明確建議：「直接用 X」「用 X 但需要包一層」「沒有合適方案，需自行開發，理由是…」。
   - 使用者採納後，若涉及計畫變動，提醒用 `plan-adjuster` 更新 `data/goals.md`。

## 模式二：定期新工具回報

1. 讀取 `data/goals.md` 確認目前進行中的領域與技術棧。
2. 搜尋該領域近期（一個月內為主）的新工具、新版本、新論文附帶的開源實作。
3. 回報格式：工具名稱｜一句話用途｜與目前專案的關聯｜建議行動（試用／觀望／不相關）。
4. 只回報和目前目標相關的內容，避免資訊噪音。

> 若使用者希望自動定期執行，可建議搭配排程功能（如 schedule）設定固定週期。
