# dev-logger：踩坑紀錄

## 目的

把「試過但不行」的經驗變成可查詢的 memory：
- 開發時先查 dev-log，避免重複踩同一個坑。
- 日後 `weekly-report` 和 `story-builder` 都會取用這些紀錄。

## 觸發時機

- Agent 在開發過程中發現某個方法不可行。
- 使用者說出「這方法不行」「之前試過失敗了」之類的話。
- 每次工作結束時的固定確認（見 CLAUDE.md）。

## 執行步驟

1. **先查重**
   - 讀取 `data/dev-log/` 現有紀錄，確認這個坑是否已記錄過。
   - 已記錄過 → 不重複建檔，必要時在原紀錄補充新資訊。

2. **蒐集資訊**
   - 向使用者（或從對話脈絡）確認四個欄位：
     - 嘗試的方法：做了什麼、怎麼做的
     - 為何失敗：具體的失敗現象與根本原因（盡量到根因，不只寫表象）
     - 替代方案：後來改用什麼，或目前的候選方向

3. **寫入紀錄**
   - 在 `data/dev-log/` 建立檔案，命名：`YYYY-MM-DD-<簡短主題>.md`。
   - 固定格式：
     ```markdown
     # <簡短主題>

     - **日期**：YYYY-MM-DD
     - **嘗試的方法**：<描述>
     - **為何失敗**：<現象 + 根本原因>
     - **替代方案**：<改用什麼／候選方向>
     ```

4. **收尾**
   - 向使用者確認紀錄內容無誤。
   - 提醒：之後開發相關功能前，agent 會先查閱 dev-log。
