# 投影片公式排版的四個地雷（pptxgenjs / PowerPoint）

- **日期**：2026-08-15
- **嘗試的方法**：用 pptxgenjs 產生 RMP 論文投影片，公式直接以純文字寫入（`x_g`、`argmin_q̈`、`^𝒳`、`𝓡`）。
- **為何失敗**：連續踩到四個渲染問題，每個都要重生成一輪才發現：
  1. **底線下標被原樣印出**：投影片沒有 LaTeX，`x_g` 會顯示成 `x_g`。
  2. **代理對字元被切成兩半**：`^𝒳` 這類 BMP 以外的數學字母是 UTF-16 代理對（兩個碼元）。自製的上下標解析器用 `str[i+1]` 只取一個碼元，字被切半，畫面出現兩個 `?` 方框。
  3. **行內上下標弄斷項目符號**：pptxgenjs 在含上下標 run 的段落會提前斷段，導致該項目的 bullet 消失、句子被切成兩行。
  4. **字型缺字**：`𝓡`（U+1D4E1 粗體花體 R）在 Arial 缺字，直接消失不見。
- **替代方案**：
  1. 用 pptxgenjs 的 `subscript` / `superscript` 產生真正的上下標格式。
  2. 取單一字元一律用 `String.fromCodePoint(str.codePointAt(i))`，長度用該字串的 `.length` 前進。
  3. 符號只放在公式卡片（單一文字方塊）中；正文項目符號改寫成文字敘述，或使用 Unicode 下標（ᵢ、ᵣ、₀）。
  4. 花體字改用 `ℛ`（U+211B），且只在數學字型（Cambria）的公式卡片裡使用。
  5. **流程層面**：每次重生成後一定要轉圖片逐頁看過——這四個問題全部無法從程式碼看出來，只有渲染後才會現形。規則已寫入 `skills/research/slide-maker/SKILL.md`。
