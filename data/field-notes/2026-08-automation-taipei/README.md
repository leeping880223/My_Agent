#### 1. 工研院 資通所｜「照片級擬真 3D 模型建構與展示技術」VenReal 3D ★★★ 對論文最有用

講者：吳欣怡 技術經理（現場）

- **技術**：3D Gaussian Splatting（3DGS）。技術演進 MVS/SfM → NeRF(2020–2022) → **3DGS(2023~)**；流程為 SfM 初始點雲 → 神經網路優化 3D Gaussians → 輸出 `.ply`
- **工具鏈**：iOS APP／Web 拍照 → 雲端 3DGS 建模 → 儲存 → Web Viewer 展示，模型可下載
- **成本對比（他們的數字）**：傳統 3D 建模約 **3 萬元／4 人天**；3DGS **0.5–1 小時／次**，宣稱擬真還原度 95% 以上
- **拍攝要領**：繞物體上／中／下各一圈；**反光或結構複雜處要多拍**；**透明或高反光物體拍攝難度較高**
- **本人已實測（現場）**：當場用 APP 掃了展台上的公仔——APP 流程為 Detecting Plane and Object → 自動生成 37 個建議拍攝點 → Auto Capturing 拍到 93 張 → Finish。**整套流程本人已經跑過一次**
- **限時活動（現場 DM）**：Q1024 攤位，加 LINE 官方帳號輸入通關密語 **「AUTO2026」**，**2026/09/05 截止**；成功建模回傳可獲延長免費試用 1 個月 ＋ 2 次模型處理服務；展期間可預約現場為展品拍照建模
- **對論文的意義（2026-08-20 更正，重要）**：3DGS **不能**直接拿來當 Isaac Sim 的資產。
  - **3DGS 輸出的是點狀高斯（`.ply` 點雲），沒有面（mesh），因此帶不進 collision（碰撞性質）**。Isaac Sim 要的是 **mesh／USD**，有面才有碰撞、才能做抓取模擬
  - 3DGS 適合的是「看起來像」的展示用途（Web Viewer、平板展品導覽），這也正是工研院這個產品的定位
  - **工研院給的替代建議**：用 **NeRF** 或 **Meta 的 SAM 3D** 走掃描重建路線
  - **現實成本（工研院自己的說法）**：他們一般是自己手動「拉」模型，**一個器械大約要花 1 小時**；而且**必須有實體器械在手**，才知道真實尺寸規格
  - ⚠️ 另外仍要記得他們自己講的限制：**高反光金屬件（手術器械正是）拍攝難度高**
  - ⬜ 3DGS 試用尚未做（密語 AUTO2026，2026-09-05 截止）；**但依上面的判斷，優先度已下降**——真正該評估的是 NeRF／SAM 3D → mesh → USD 這條路

## 跨公司的四個觀察（分享報告可以用這個當骨幹）

1. **人形機器人在台灣已經形成完整供應鏈，而不是單點嘗試**
   關節／傳動（上銀、富田）→ 控制器與邊緣運算（研華、磐儀）→ 整機與代理（達明、台智寶、至盛/Unitree）→ 應用與 SI（Solomon、新代）。同一個展場走一圈就能把上下游看完。
2. **「模擬先行」成為公開的方法論**
   達明用 Isaac Sim ＋ GR00T 合成資料、研華畫出六階段數位孿生藍圖、新代用數位孿生做部署前規劃。**共同邏輯：真實資料太貴，先在模擬裡練。**
3. **LLM／VLA 進到機器人，但分工很清楚**
   FANUC 是 LLM 產生高階 API 呼叫；Solomon 是語言指令驅動人形完成移動＋抓取；研華直接把「傳統 code-based vs VLA」並排比較。**現階段是「語言當介面、傳統控制當底層」，不是端到端取代。**
   對照組：新代明講「真正多用途人形還很遠」——展場上有樂觀也有保留，報告時兩邊都講會更有說服力。
4. **「AI 視覺」四個字底下，實力差兩個數量級**
   同樣掛 AI 視覺：EverFocus 的顏色分類 **7.9 FPS**、達明骰子辨識**單次 1449 ms**、ASUS×YASKAWA 的曲棍球對戰 **284 FPS／推論 25 ms**。差別在於任務難度與硬體投入——**看 demo 一定要問 FPS 與推論時間，不然全是「有 AI」**。這也是報告裡最容易讓人記住的一組數字。

## ★ 論文方向：展場所見與教授 7/28 提的方向對上了

**先講前提（2026-08-20 補）**：VLA 不是逛完展才冒出來的想法。**2026-07-28 Basanta 教授就已經提出並命名**——*Autonomous Surgical Instrument Manipulation Using **Vision-Language-Action Models** in Isaac Lab*，還給了 10 步驟進程並指定聚焦 4–10（完整內容已寫進 [goals.md](../../goals.md) 的「論文題目與方向」一節）。**展場兩天的所見，等於是產業替這個方向背書。**

**使用者當天的原話（口述，先寫下來以免只留在對話裡）**：

> 本來想做變焦鏡頭相關的，像是索羅門這樣，但工研院可能比較想要用 VLA、並且是可以用 chatbox demo 這樣。今天看得比較偏向這類型的。

**三方期待（2026-08-20 補述）**：
- **工研院**要推的是 **VLA 應用：可以下達指令，未來同一個指令可以下給多台機器人**；另外也想要人形會走路，但**使用者判斷走路目前沒有好的應用場景**
- **醫院 CSSD 的真需求是「打包」（組成器械包）**，但現階段做不到
- **Yang 教授**：已**口頭同意要簽**，這關等於過了，不再是阻礙
- **⚠️ Basanta 教授的專長是影像**——所以**論文重心要維持在影像／視覺相關**，不能整份押在語言層

### 兩條路的對照

| | **A. 視覺路線（原本的想法）** | **B. VLA ＋ chatbox 路線（8/20 傾向）** |
|---|---|---|
| 對標對象 | Solomon 的 3D 視覺取放、變焦／可變焦鏡頭取像 | 台達 具身智能雙臂平台、FANUC Physical AI、Solomon 人形語言指令 |
| 現有資產 | **強**：YOLO 分割 mAP50≈0.9、Replicator 合成資料 pipeline、2D→3D 座標轉換已跑通 | **中**：Isaac Sim／RMPflow／G1＋Dex3 都有，但**沒有 LLM／VLA 這一段** |

### 關鍵觀察

1. **B 不是砍掉 A，而是把 A 包起來。** 展場上每一家的架構都是同一句話：**LLM／VLM 當大腦（理解、規劃），傳統視覺與控制當小腦（執行）**（台達的投影片寫得最白：大腦＝VLM|LLM|GPU，小腦＝EtherCAT|工控）。FANUC 的 `ROBOT_CONTROLLER.PY` 也是 LLM 呼叫既有的 `pick_letter()`。所以現有的 YOLO ＋ RMPflow ＋ Dex3 抓取正是「小腦」，**上面加一層對話介面即可**。
2. **工研院自己就在做手術器械分揀 demo**（見 Day 2 第一節），但那是**固定式雙臂、單台**。工研院真正想推的是**「同一個指令下給多台機器人」**——這正是他們展場 demo 還沒做到、而教授 10 步驟清單第 9 項（Human-robot collaboration）涵蓋得到的地方。**差異化的空隙可能就在這裡。**
3. **chatbox demo 的邊際成本不高**：`「幫我把剪刀放到綠色布上」→ 解析出 (動作=放置, 物件=剪刀, 目標=綠布) → 呼叫既有 pick&place` 就能成立，不必一開始就上端到端 VLA。
