# 性向分析結果

由 interest-tracker 彙整 [task-feelings.md](task-feelings.md) 產出，供 job-matching 和 story-builder 使用。

## 性向摘要

**一句話：他享受的是「把混亂的東西變清楚、然後讓它自己跑起來」，而且成就感來自別人也因此受惠。**

這條主線在**六年、三種身分**下都出現過同一個形狀，不是最近才有的偏好：

| 時期 | 事件 | 形狀 |
|---|---|---|
| 台積電（2022–2024） | **EMO cover 管理**：種類多、亂貼、多餘庫存堆著而真正缺的找不到 → 自己做表格管理 | 把混亂變有序。**明說「對產線 KPI 完全沒有貢獻」**，純粹看不下去 |
| 台積電 | **SOP 改版**：新機型卻用舊 SOP → 補上細節與原理，出最新版 | 「**本來就想把它寫清楚**」，不是為了拿獎（獎是後來的結果） |
| 台積電 | **自學 Excel VBA**：機台文字報告 → 巨集 → 篩出重要數值看趨勢 | 自動優化流程 |
| 碩士申請（2024-11） | 看到碩士同事用**自動化動態控制 EUV 參數**，「我也希望能與他們一樣」 | 「**軟體自動控制硬體**」 |
| 碩士（2026） | **chatbox**：一句話讓機器人自己做完 | 同上，換了載體 |
| 碩士（2026） | **自建 agent 系統**（skills ＋ data 分層） | 把自己的工作流程自動化 |

**使用者自己的總結**：「喜歡東西是清楚的，然後自動優化流程，這是我很喜歡的事情。」

## 喜歡的任務類型與原因主題

1. **把混亂整理成有序** —— 最強的一條。EMO cover、SOP、知識地圖、agent 系統都是。
2. **往前推進、變清楚的過程** —— 梯子教學（2026-08-15「喜歡」）、把散落的東西收斂成可執行的計畫（2026-08-20「喜歡」）都被點名。**重點是「走上去」，不是「被測驗」。**
3. **從痛點出發解決問題** —— Basanta 的評語：「他是根據痛點來解決事情，所以做出來的東西比較有水準。」EMO cover 也是同一個模式。
4. **讓別人也受惠** —— 「如果他們能在 SOP 中獲救，我也覺得很開心」；「人就是要互相幫忙，我也很樂於分享我知道的知識」。**成就感的來源不是個人績效。**
5. **對等的知識交換** —— 「我不知道的他跟我講，他不知道的我跟他講，這種互相交流是我喜歡的。」
6. **打磨自己的工具與系統** —— 但**有條件**：「不忙的時候會去搞，忙起來可能就沒空。」（2026-08-17）

## 不喜歡的任務類型與原因主題

1. **被動接受測驗或大量資訊** —— 純問答測驗不帶來收穫感（2026-08-18「普通」）。同樣的內容改成搭鷹架就變「喜歡」。
2. **地位遊戲、為了電而電** —— 「明明知道那件事根本不重要……很明顯就是想電人。」多發生在交接。**他也不去電別人**，連報復心態都不喜歡。
3. **自私自利、不管別人死活** —— 對楊老師的評價。且他有明確界線：「當主管為了公司利益顯得自私自利還算合理，**當老師這樣就不好**。」
4. ⭐ **結構上突破不了的限制** —— 2026-08-22 排除 SI 時的原話：「**不喜歡這種突破不了的限制**」。**不是討厭困難，是討厭「再怎麼做也頂不開」**——天花板由生意模式決定、努力不會改變結果的位置。這條與主線一致：他做的事一直是「把卡住的東西弄通」（EMO cover、SOP、VBA、chatbox），而一個結構上通不了的地方，等於把他最想做的事拿掉。
5. **長期的地理與通勤消耗** —— 不接受在台南六甲當正職（「有夠遠、有夠偏僻」），但**短期出差可以也樂意**；住新竹通勤到桃園也不接受（每天超過半小時、且無自用車）。**排斥的是「每天」的消耗，不是「去一趟」。**

## 工作方式的模式（給排程與決策用）

- **不是持續高衝勁型，是「決定了就做好」型**（自述）。→ **決策品質比動力管理重要**：把事情想清楚、砍掉不做的，比催進度有效。
- **多線並行很消耗**。上學期末兩競賽＋期末考＋專題＋實習，熬過去了但「累到快死掉」。→ 排程留餘裕，不要排滿。**但要記清楚：四條線他都撐住了，產出是一個第一名加一個第二名——那學期垮掉的是別人給的方案，不是他。**
- ⭐ **會自己驗可行性，而且驗出來就敢喊停。** 這是他兩次躲過死題目的原因。→ **給他的任何方案，都要附上「怎麼驗這件事做不做得出來」，他會真的去驗**；反過來，只給結論不給驗證方法的方案，他會（正確地）不信。
- **有現實依據時決策果斷**（行走降級、3DGS 排除、硬體不追新，都是一句話定案）；**卡住的一律是「別人期待什麼」**（教授想要什麼、分工怎麼分、口委怎麼看）。→ 遇到外部不確定性時，把它轉成**可觀察的判準與時間點**（例：2026-11 的閘門），比繼續分析有效。
- **系統要能一次設好自己跑**，不能靠他定期維護——忙起來會先失效的東西不要當成計畫的支柱。

## 與目前職涯方向的相符度

**相符**：`current-plan.md` 的興趣主線（自動化與提升工作效率）與本分析完全一致，且有六年的跨情境證據。**T2b（自動化與控制軟體）** 最貼近；**T1a／T3（缺陷檢測、AOI）** 也符合——「用機器取代人工目檢」正是把混亂變有序。

**要留意的三點**：

1. **「讓別人受惠」這個成就感來源，在偏個人績效的環境會失效。** 選部門時要問「這裡的人會不會互相教」，這比薪資級距更能預測他待不待得住。
2. **避開以電人為文化的地方。** 這在半導體與外商都存在，面試時要刻意觀察。
3. **驅動力不是錢，而且存款已接近頭期款門檻**（見 current-plan）——所以「先忍幾年高薪」這種安排撐不住。**第一階段若滿足不了「把東西變清楚」，他會待不下去。** 排序時工作內容的權重要高於薪資級距。
